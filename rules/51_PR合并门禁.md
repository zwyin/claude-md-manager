## PR 合并门禁

推送到 GitHub 的项目，合并 develop → master 的 PR 之前必须：

1. **检查 CI 状态**：合并前必须运行 `gh pr checks <number>` 查看 PR 的所有 CI check 结果
2. **修复新增报错**：如果改动引起了新的测试失败（特别是跨平台差异），必须先修复这些报错，推送到 develop 分支更新 PR，确认 CI 全部通过
3. **禁止绕过**：不得在 CI 有新增失败时直接合并 PR
4. **跨平台注意**：GUI 测试在 macOS/Linux/Windows 上行为可能不同（QSettings、路径格式、线程），修复时要考虑跨平台兼容性

### 流程

```
创建 PR → 检查 CI → 有新失败？
                          ├─ 是 → 修复 → 推送更新 PR → 重新检查 CI
                          └─ 否 → 合并
```

### 适用范围

- 所有推送到 GitHub 并通过 PR 合并到 master 的项目
- 本地-only 的改动不受此规则约束
